# Echoes — Design Log (Chat Extract)
Date: 2026-02-04

## Core loop UX (canonical)
- Roll dice.
- Highlight available actions.
- Click an action.
  - If action is targeted: cursor becomes crosshair; highlight eligible hexes; click target.
  - If action is untargeted: resolves immediately.
- Consume the die/dice used by that action.
- Recompute available actions from remaining dice.
- Repeat until no dice remain.
- If an action triggers a modal (card draw/choice, combat choice, event), disable/grey action UI until resolved.

## Dice model (simplified)
- Roll 2d6 each round (A, B). First player also gets Bonus die.
- Each die can be used once.
- Possible combinations: A, B, A+B, A & Bonus, B & Bonus, A+Bonus, B+Bonus.

## Fog of war / exploration
- Do NOT reveal fog by clicking fogged hexes.
- Fog is revealed only via:
  - An action (scan / reveal), OR
  - Moving a fleet into a fogged hex.
- Map clicks should select hexes as targets, not trigger reveal (unless dev/free-explore mode).

## Directorate action naming
- Rename “Patrol Sector” to “Long Range Sensor Scan”.

## Modal locks
- When a card is drawn or combat/event choice occurs:
  - Grey out / disable action panel and roll button.
  - Resume only after modal resolves.
  - Dice are consumed only after the modal resolves.

## Cards: “reverse-side placement note”
- Every card should display (on resolved/back side):
  - Outcome text
  - “Place in hex:” instruction specifying what token to put in the cell.
- Data-driven via:
  - placeNote, or
  - placeNoteByChoiceIndex, or
  - derived from resolved tokenId (fallback)
  - or “Place: Nothing”.

## Standard token set (18-piece vocabulary)
Systems & infrastructure:
- capital_directorate, capital_choir, capital_bloom
- colony, outpost, mining_outpost, research_array, trade_route

Space / empty encounters:
- debris_field, derelict, pirate_den, neutral_enclave

Phenomena / ancient:
- ruins, anomaly, hazard, gate, beacon

Bloom:
- biomass

## Crosshair cursor targeting
- Targeting actions must:
  - enter state ui.mode="targeting"
  - add a map container class (e.g., `.map.targeting`) that forces `cursor: crosshair !important;`
  - highlight eligible hexes
  - reject invalid target clicks with a clear log message

## Layout direction (boardgame readability)
- No page scroll. Internal scroll only (log/card).
- Right column: card larger than log.
- Bottom: actions grouped (1–6, 7–12, 13–18) in bottom-right; dice controls bottom-left.
- Remove multiple dice-spend buttons; roll once and highlight actions.

## Influence / ownership (concept)
- Each faction has influence per hex explored/visited; proximity and presence modify it.
- Highest influence = controller; 2nd place can receive reduced benefit on activation.
- Forward Deploy recruits into a system you control (targeted action).

## Combat concept (later spec)
- Combat occurs when moving into a hex with other faction fleets and choosing to engage.
- Dice pairing high-to-high; loser of each pair takes a hit.
- Hits flip undamaged to damaged, then remove damaged.
- Post-round: continue or retreat; retreat goes to orthogonally adjacent hex with most influence and no enemy ships, otherwise cannot retreat.
- Multi-faction sides allowed; neutral factions may join either side.
- System controller wins combat ties.
- Fast Deployment move (2 hex) cannot enter enemy-occupied hex.

## Fleet storage (future-proof)
- Option C hybrid suggested:
  - fleetsByHex[hexId][factionId].undamaged[] / damaged[] fleet IDs
  - fleetMeta[fleetId] contains faction and later tags/upgrades
